# Политика конфиденциальности (Privacy Policy)

**Последнее обновление:** 16 августа 2026 г.

Эта Политика описывает, как **Purgito** собирает, использует, хранит и защищает информацию, необходимую для предоставления своих функций.

Purgito — публичный бот Discord, используемый на множестве серверов. Данные, которые мы собираем, и то, как мы их обрабатываем, одинаковы для всех серверов, где присутствует бот.

---

# 1. Собираемая информация

Для корректной работы бот может хранить следующую информацию:

## Информация Discord

- ID пользователей.
- ID серверов.
- ID каналов.

Эти идентификаторы используются исключительно для внутренней работы бота.

---

## Содержимое сообщений

Когда функции обучения включены, бот сохраняет содержимое текстовых сообщений, отправленных в разрешённых каналах.

Эти сообщения могут использоваться для:

- Обучения локальных цепей Маркова.
- Генерации автоматических ответов в чате.
- Имитации стиля письма пользователей.
- Служить ограниченной выборкой лексики при генерации мемов (локально с помощью Маркова или через опциональную интеграцию с Groq, если она настроена).

Каналы, помеченные в Discord как **NSFW**, всегда исключены из этого обучения: Purgito никогда не сохраняет сообщения из NSFW-канала, без исключений и без возможности включить это вручную для корпуса. Если канал, уже разрешённый для корпуса, позже помечается как NSFW, уже сохранённая история этого канала немедленно удаляется.

---

## Мультимедиа

Бот может хранить:

- URL изображений.
- URL GIF.
- Медиафайлы, необходимые для функций галереи GIF и коллекции мемов.

Когда это применимо, такие файлы могут храниться на постоянной основе через Cloudflare R2.

---

## Отображаемое имя

Отображаемое имя (Display Name) пользователя может сохраняться вместе с определёнными сообщениями, чтобы обеспечить такие функции, как имитация пользователей.

---

## Вход в веб-панель

При входе на purgito.app через Discord запрашиваются разрешения (scopes) `identify`, `email` и `guilds`. Это позволяет показывать тебе твоё имя пользователя, аватар и почту в рамках твоей собственной сессии, а также связывать твой аккаунт Discord с серверами, которыми ты управляешь (scope `guilds` позволяет узнать, на каких серверах у тебя есть права администратора, чтобы показывать в твоей панели только их). Сохраняется сессионная cookie, чтобы держать тебя авторизованным во время навигации по сайту; эта cookie не используется в рекламных целях или для отслеживания между сайтами.

---

## Журнал аудита панели

Когда администратор вносит изменение в настройки через веб-панель (команда `/settings`), Purgito сохраняет собственный журнал аудита этого сервера: ID Discord и отображаемое имя того, кто внёс изменение, тип действия (например, добавление особой фразы, добавление GIF или очистка корпуса канала) и, в некоторых случаях, произвольный текст, который может включать содержимое, написанное дословно тем, кто внёс изменение.

Этот журнал виден только администраторам того же сервера, на вкладке «История» панели, и существует для того, чтобы сообщество могло видеть, какие изменения были внесены и кем. Он хранится максимум 90 дней, после чего автоматически удаляется (см. «Хранение данных»).

Бот **не собирает**:

- Пароли.
- Электронную почту, за исключением той, которую предоставляет Discord при входе в веб-панель (purgito.app) — эта почта используется исключительно для идентификации тебя в рамках твоей собственной сессии и не передаётся третьим лицам.
- Персональные данные, не предоставленные официальным API Discord.

**IP-адреса:** дашборд (purgito.app) обрабатывает твой IP-адрес временно и в ограниченном объёме, исключительно для предотвращения злоупотреблений (ограничение частоты запросов). Этот IP хранится только в памяти процесса в течение короткого окна (от секунд до минут), никогда не сохраняется в базе данных или каком-либо постоянном журнале и не передаётся третьим лицам.

О платёжных данных см. раздел **«Платежи и подписки»** ниже: Purgito их не хранит, но процессор платежей (Polar.sh) собирает их при обработке покупки.

## Платежи и подписки

Когда сервер оформляет premium через дашборд (purgito.app), платёж обрабатывает **Polar.sh**, а не Purgito.

**Purgito хранит только:**

- ID сервера (guild_id) с активным premium.
- Дату активации.
- Текстовую заметку, определяющую план (например, «Polar — месячный» или «Polar — годовой»).

Purgito **не хранит** номер карты, платёжные данные, email или имя покупателя.

**Polar.sh собирает** данные, необходимые для обработки платежа (карта, email, платёжные данные), в соответствии со своей собственной [Политикой конфиденциальности](https://polar.sh/legal/privacy). Эти отношения по данным существуют между покупателем и Polar.sh как процессором/Merchant of Record.

# 2. Использование информации

Собранная информация используется исключительно для предоставления функций бота, включая:

- Генерацию текста с помощью локальных цепей Маркова.
- Генерацию мемов и captions (локально или через опциональную интеграцию с Groq).
- Галерею GIF.
- Автоматизации сервера.
- Настройку команд и предпочтений.

Данные **не продаются** и не используются Purgito для рекламы.

# 3. Сторонние сервисы

Purgito использует внешние сервисы для определённых функций. Каждый провайдер обрабатывает только ту информацию, которая необходима для предоставления его услуги.

## Discord и хранилище

- **Discord**: для коммуникации, получения событий, аутентификации и отправки сообщений на платформе.
- **Cloudflare R2**: для постоянного хранения медиафайлов (изображений мемов из пула сервера и GIF, загруженных в галерею).

## Groq API (Captions мемов с ИИ)

- **Что это и для чего используется**: Groq — внешний провайдер инференса моделей искусственного интеллекта (зрение и язык), используемый опционально и исключительно для анализа изображений и составления captions в функции мемов.
- **Какие данные могут отправляться**: изображение, используемое для мема (закодированное в base64), и ограниченная выборка корпуса сервера (до 25 коротких сообщений и 15 длинных сообщений в качестве образца лексики и тона).
- **Когда это происходит**: только при запросе или выполнении генерации мема (команда `/momo`, ответ по триггеру на изображение или запланированный мем), и только если ключ `GROQ_API_KEY` настроен оператором бота.
- **Ограниченный охват**: Groq не обрабатывает обычные разговоры в чате и не получает полный корпус какого-либо сервера. Общий чат Purgito работает на 100% локально.
- **Локальный fallback**: если Groq не настроен, недоступен или даёт сбой, генерация caption выполняется на 100% локально с помощью цепей Маркова.
- **Реклама**: данные, передаваемые в Groq в рамках этой функции, не используются Purgito в рекламных целях или для продажи данных.

## Платежи и инфраструктура

- **Polar.sh**: процессор платежей и Merchant of Record для premium-подписок. См. его [Политику конфиденциальности](https://polar.sh/legal/privacy).
- Другие инфраструктурные сервисы, строго необходимые для работы бота.

# 4. Хранение данных

Собранные данные хранятся только до тех пор, пока они необходимы для работы бота.

История сообщений не хранится бессрочно, даже пока сервер активен: у каждого сервера есть максимальная квота сохранённых сообщений (больше на серверах с Premium). При достижении этой квоты самые старые сообщения автоматически отбрасываются по мере сохранения новых, без необходимости ручного вмешательства администратора.

Администраторы сервера также могут в любой момент удалить собранный контент через интерактивную панель настроек (команда `/settings`), которая включает кнопки для очистки корпуса выученных сообщений и удаления сохранённых GIF.

Журнал аудита панели (см. раздел 1) хранится максимум 90 дней с момента каждой записи, после чего автоматически удаляется без ручного вмешательства.

Когда бот покидает сервер (например, если его исключают), данные этого сервера сохраняются в течение 30-дневного льготного периода перед полным удалением. Это нужно для того, чтобы, если бота снова пригласят в течение этого срока, сервер восстановил свою конфигурацию и контент, не начиная с нуля. В течение этого периода, пока бота нет на сервере, нет способа получить доступ к панели администрирования для управления этими данными. На сегодняшний день не существует способа самостоятельно ускорить это удаление на уровне сервера до истечения 30 дней; если ты администратор сервера и хочешь, чтобы его данные удалили раньше этого срока, можешь запросить это, связавшись с разработчиком (см. «Контакты» ниже).

## Удаление твоих собственных данных (право на забвение для отдельного пользователя)

Независимо от вышесказанного, любой пользователь может в любой момент запросить удаление своей собственной информации, не завися от того, является ли он администратором какого-либо сервера, и не дожидаясь 30 дней из предыдущего пункта.

Команда `/borrar_mis_datos`, доступная любому человеку на любом сервере, где есть Purgito, безвозвратно и немедленно удаляет на **всех** серверах, где ты писал:

- Твой сохранённый стиль письма для функции имитации (`/imitar`).
- Сообщения, которые Purgito выучил у тебя для генерации текста.

Твои оригинальные сообщения в Discord не затрагиваются: это удаляет только копию, которую Purgito сохранил, чтобы учиться на твоей манере письма. Поскольку это необратимое действие, команда запрашивает явное подтверждение перед выполнением удаления.

Это удаление специально предназначено для описанных выше данных обучения на сообщениях и не покрывает автоматически другие категории, которые ты мог создать на сервере — например, GIF или изображения, которые ты добавил в пул сервера, или твоё собственное появление в журнале аудита панели, если ты администратор — поскольку они привязаны к серверу, на котором были созданы, а не только к твоему аккаунту. Если ты хочешь запросить удаление чего-либо из этого, можешь связаться с разработчиком (см. «Контакты»).

# 5. Права пользователей

Любой пользователь может удалить свою собственную информацию в любой момент с помощью команды `/borrar_mis_datos` (см. раздел 4), без необходимости быть администратором какого-либо сервера.

Администраторы сервера также располагают собственными инструментами для контроля сбора данных своего сообщества (см. раздел 4), включая возможность исключать конкретных пользователей: независимо друг от друга они могут отметить, что Purgito не должен взаимодействовать с этим пользователем (не отвечать ему, не реагировать и не срабатывать по триггерам) и/или не должен учиться на его сообщениях (не использовать их для корпуса и функции имитации).

Если ты считаешь, что существует информация, которую следует удалить и которая не покрывается этими инструментами самообслуживания, или у тебя есть вопросы об обработке данных, ты можешь связаться с разработчиком.

Когда это технически возможно, обоснованные запросы на удаление информации будут выполнены.
