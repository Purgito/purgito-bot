API

La API de Purgito es una interfaz REST JSON asíncrona construida sobre aiohttp.web. Se ejecuta dentro del mismo proceso del bot en 127.0.0.1:WEB_PORT y es expuesta hacia internet de forma segura mediante el proxy inverso de Nginx.

Autenticación OAuth2 y Sesiones

El acceso al dashboard utiliza el flujo estándar de autorización OAuth2 de Discord (Authorization Code Flow):

  1. GET /auth/login genera un parámetro state criptográficamente seguro con secrets.token_urlsafe(32) y redirige al usuario a la página de consentimiento de Discord con los scopes identify, email y guilds.
  2. Discord redirige a GET /auth/callback con el código de autorización y el state.
  3. El servidor intercambia el código por un token de acceso mediante https://discord.com/api/v10/oauth2/token, obtiene el perfil del usuario y los servidores que administra (/users/@me/guilds). Si el usuario no administra ningún servidor donde el bot esté presente o disponible, la autenticación se deniega.
  4. Se emite una cookie de sesión cifrada simétricamente mediante Fernet (SESSION_SECRET) con las propiedades HttpOnly, SameSite=Lax y Secure.

Para invalidar sesiones sin almacenar un estado pesado en memoria, la tabla revoked_sessions almacena los identificadores de sesión cerrados explícitamente mediante POST /auth/logout. Cada petición entrante comprueba que el ID de la sesión no figure en dicha tabla.

Endpoints por Servidor (/api/server/{guild_id}/*)

Todas las rutas bajo este prefijo requieren sesión activa y validan en tiempo real que el usuario tenga el permiso Administrar Servidor (o el rol de Gestor, con acceso más acotado) en el servidor solicitado:

  • GET /api/server/{id}/channels, /roles, /emojis: Listas crudas del servidor para alimentar los selectores del panel.
  • GET/POST /api/server/{id}/style: Consulta y actualización de avatar, apodo y banner de Purgito en el servidor.
  • GET/POST /api/server/{id}/stats, GET .../stats/activity: Métricas de memoria de mensajes, GIFs, frases, actividad histórica y cuotas.
  • GET/PUT /api/server/{id}/settings/chat, PUT .../settings/chat/tunables: Ajustes de generación, probabilidades de respuesta y límites de mensajes.
  • POST /api/server/{id}/chat/playground: Simulador de respuestas del chat sin publicar nada en Discord.
  • GET/PUT /api/guilds/{id}/channels/{channel_id}/settings: Override de ajustes de chat para un canal puntual.
  • GET/POST/DELETE /api/server/{id}/settings/spontaneous-channels: Canales donde el bot habla por su cuenta.
  • GET/POST/DELETE /api/server/{id}/settings/mention-channels: Canales donde responde a menciones.
  • GET/POST/DELETE /api/server/{id}/settings/corpus, POST .../settings/corpus/amnesia: Canales de los que aprende y vaciado del corpus. Los canales completamente silenciados (ignored_channels) no tienen endpoint propio — se administran con /settings en Discord.
  • GET/POST/DELETE /api/server/{id}/settings/exempt-roles, .../settings/exempt-channels: Roles y canales exentos del límite de menciones.
  • GET/POST/PUT/DELETE /api/server/{id}/settings/excluded-users: Usuarios excluidos del aprendizaje.
  • GET /api/server/{id}/members/search: Búsqueda de miembros para selectores del panel.
  • GET/POST/DELETE /api/server/{id}/settings/reacciones: Reglas de reacción automática con emojis.
  • GET/POST/DELETE/PATCH /api/server/{id}/settings/frases (+ /channels) y /api/server/{id}/frases/packs (+ /channels): Frases especiales, sus canales asignados y sus packs.
  • GET/POST/DELETE /api/server/{id}/settings/triggers: Respuestas automáticas por coincidencia exacta, prefijo o expresiones regulares (regex).
  • GET/PUT /api/server/{id}/settings/updates, .../settings/prefix, .../settings/manager-role: Canal de novedades, prefijo de comandos y rol de Gestor del servidor.
  • GET/POST/DELETE /api/server/{id}/settings/gifs (+ /senders, /by-user/{user_id}, /verify, /blocked, /{gif_id}/block): Catálogo de GIFs, atribución por usuario, verificación y lista de bloqueo.
  • GET/POST/DELETE/PATCH /api/server/{id}/youtube, /twitch, /rss: Suscripciones y canales de alerta para YouTube, Twitch y feeds RSS/Atom genéricos.
  • POST /api/server/{id}/embeds/send, /share, /schedule, /validate, /upload, /upload-file/{filename}, /resolve-gif, GET .../uploads: Editor de embeds — envío, enlaces compartibles, programación, validación y subida de archivos.
  • GET/POST/PUT/DELETE /api/server/{id}/embeds/templates: Plantillas guardadas del diseñador de mensajes.
  • GET/POST/PUT/DELETE /api/server/{id}/anuncios: Programación y gestión de anuncios automatizados.
  • GET/PUT/DELETE /api/server/{id}/events, /events/{event_type}, POST .../test: Consulta, configuración (texto plano, embed clásico, Layout V2) y prueba de eventos de Bienvenida, Despedida y Boosts con motor de variables.
  • GET /api/server/{id}/premium, POST .../premium/checkout: Estado Premium del servidor e inicio de la sesión de pago en Polar.
  • GET /api/guilds/{id}/audit: Registro de auditoría de cambios realizados desde el dashboard (nota el prefijo /guilds/, distinto al resto).

No existe un endpoint dedicado a imágenes del banco de memes: esa función se administra íntegramente desde Discord (reacciones y comandos), sin superficie en el dashboard todavía.

Webhooks de Pago (Polar)

POST /webhooks/polar recibe notificaciones de eventos de suscripción y facturación emitidos por Polar:

  • Verificación de firma: Se valida la cabecera Webhook-Signature utilizando el estándar Standard Webhooks (HMAC-SHA256) con el secreto POLAR_WEBHOOK_SECRET. Si la firma es inválida o falta la cabecera, la petición se rechaza con código 400.
  • Orden de eventos: Cada payload incluye marcas temporales para garantizar que eventos desfasados en la red no sobreescriban estados más recientes.
  • Eventos procesados: subscription.active y subscription.resumed otorgan Premium; subscription.paused y subscription.revoked lo retiran; subscription.created con estado trialing cuenta como alta (arranca la prueba de 7 días); refund.created/refund.updated revocan el acceso si el reembolso se confirma y el objeto trae revoke_benefits. Todo esto actualiza en tiempo real la tabla premium_guilds. subscription.updated/subscription.canceled no otorgan ni quitan acceso por sí solos, pero sí actualizan la metadata de facturación en premium_subscriptions (plan, período, cancelación programada) que alimenta /perfil/facturacion.
