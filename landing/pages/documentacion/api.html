API

La API de Purgito es una interfaz REST JSON asíncrona construida sobre aiohttp.web. Se ejecuta dentro del mismo proceso del bot en 127.0.0.1:WEB_PORT y es expuesta hacia internet de forma segura mediante el proxy inverso de Nginx.

Autenticación OAuth2 y Sesiones

El acceso al dashboard utiliza el flujo estándar de autorización OAuth2 de Discord (Authorization Code Flow):

  1. GET /auth/login genera un parámetro state criptográficamente seguro con secrets.token_urlsafe(32) y redirige al usuario a la página de consentimiento de Discord con los scopes identify, email y guilds.
  2. Discord redirige a GET /auth/callback con el código de autorización y el state.
  3. El servidor intercambia el código por un token de acceso mediante https://discord.com/api/v10/oauth2/token, obtiene el perfil del usuario y los servidores que administra (/users/@me/guilds). Si el usuario no administra ningún servidor donde el bot esté presente o disponible, la autenticación se deniega.
  4. Se emite una cookie de sesión cifrada simétricamente mediante Fernet (SESSION_SECRET) con las propiedades HttpOnly, SameSite=Lax y Secure.

Para invalidar sesiones sin almacenar un estado pesado en memoria, la tabla revoked_sessions almacena los identificadores de sesión cerrados explícitamente mediante POST /auth/logout. Cada petición entrante comprueba que el ID de la sesión no figure en dicha tabla.

Endpoints por Servidor (/api/server/{guild_id}/*)

Todas las rutas bajo este prefijo requieren sesión activa y validan en tiempo real que el usuario tenga el permiso Administrar Servidor en el servidor solicitado:

  • GET/POST /api/server/{id}/style: Consulta y actualización de avatar, apodo y banner de Purgito en el servidor.
  • GET/POST /api/server/{id}/stats: Métricas detalladas de memoria de mensajes, GIFs, frases, actividad histórica y cuotas.
  • GET/PUT /api/server/{id}/chat: Ajustes de generación, porcentajes de respuesta espontánea y límites de mensajes.
  • GET/PUT /api/server/{id}/canales: Matriz de canales de lectura, canales de respuesta, canales silenciados y roles ignorados.
  • GET/POST/DELETE /api/server/{id}/gifs: Catálogo de GIFs, subida de archivos y eliminación individual o masiva.
  • GET/POST/DELETE /api/server/{id}/memes: Plantillas e imágenes del banco de memes.
  • GET/POST/DELETE /api/server/{id}/triggers: Respuestas automáticas por coincidencia exacta, prefijo o expresiones regulares (regex).
  • GET/POST/DELETE /api/server/{id}/reacciones: Reglas de reacción automática con emojis.
  • GET/POST/DELETE /api/server/{id}/frases: Frases personalizadas y paquetes temáticos por canal.
  • GET/POST/DELETE /api/server/{id}/embeds: Plantillas de embeds clásicos y bloques interactivos Layout V2.
  • POST /api/server/{id}/embeds/send: Despacho inmediato de un mensaje diseñado a un canal de Discord.
  • GET/PUT/DELETE /api/server/{id}/events/{event_type}: Consulta, configuración (texto plano, embed clásico, Layout V2) y restablecimiento de eventos de Bienvenida, Despedida y Boosts con motor de variables.
  • POST /api/server/{id}/events/{event_type}/test: Envío de mensaje de prueba con variables dinámicas resueltas al canal configurado.
  • GET/POST/DELETE /api/server/{id}/anuncios: Programación y gestión de anuncios automatizados.
  • GET/POST/DELETE /api/server/{id}/youtube: Suscripciones y canales de alerta para nuevos videos.
  • POST /api/server/{id}/amnesia: Vaciado del corpus de mensajes y estilo aprendidos en las últimas 24 horas.
  • GET /api/server/{id}/audit: Registro de auditoría de cambios realizados desde el dashboard.

Webhooks de Pago (Polar)

POST /webhooks/polar recibe notificaciones de eventos de suscripción y facturación emitidos por Polar:

  • Verificación de firma: Se valida la cabecera Webhook-Signature utilizando el estándar Standard Webhooks (HMAC-SHA256) con el secreto POLAR_WEBHOOK_SECRET. Si la firma es inválida o falta la cabecera, la petición se rechaza con código 400.
  • Orden de eventos: Cada payload incluye marcas temporales para garantizar que eventos desfasados en la red no sobreescriban estados más recientes.
  • Eventos procesados: subscription.created, subscription.updated, subscription.active, subscription.canceled y order.refunded, actualizando en tiempo real la tabla guild_premium.
