API

La API de Purgito es JSON puro sobre aiohttp — no renderiza HTML en ningún endpoint. Corre en el mismo proceso que el bot, escuchando solo en localhost; nginx es quien la expone hacia afuera bajo /api/*, /auth/* y /webhooks/*.

Visión general

Dos categorías de endpoints: un puñado públicos, sin sesión (health check, estado del bot, el webhook de pagos), y los endpoints por servidor bajo /api/server/{guild_id}/..., que requieren sesión autenticada y que quien llama administre ese servidor específico.

Autenticación

OAuth2 estándar de Discord (Authorization Code flow), implementado directo sobre aiohttp sin librería de OAuth. El login redirige a Discord; el callback intercambia el código por un token, trae el usuario y sus servidores, y arma la sesión. Si el usuario no administra ningún servidor, el login se rechaza.

Sesiones

La sesión vive cifrada enteramente en la cookie (sin tabla de sesiones en el servidor) — httpOnly, SameSite=Lax, marcada segura. Como una cookie cifrada robada seguiría siendo válida hasta expirar, el logout no alcanza por sí solo: cada login genera un identificador que queda en una lista de revocación en la base, y cada request vuelve a chequear que ese identificador no esté revocado.

Por servidor — /api/server/{guild_id}/...

Requieren sesión, permiso Administrar servidor verificado en vivo contra Discord, y que el bot esté presente en ese servidor. Agrupados por área — cada grupo tiene su propio conjunto de rutas GET/PUT/ POST/DELETE:

  • Metadata del servidor: canales, roles, emojis, estadísticas.
  • Ajustes de chat: probabilidades, canales espontáneos/de mención, overrides por canal, playground de prueba.
  • Roles y canales exentos del rate limit de menciones.
  • Corpus: alta, borrado, importación, "amnesia" (reset completo).
  • Reacciones automáticas y frases especiales, incluyendo packs reutilizables.
  • Triggers configurables (regex, texto exacto, empieza-con).
  • Galería de GIFs del servidor.
  • Suscripciones de YouTube.
  • Editor de embeds: plantillas, envío, programación, subida de imágenes/archivos, links compartibles.
  • Estado de Premium e inicio de checkout.
  • Registro de auditoría de cambios hechos desde el panel.

Webhooks

POST /webhooks/polar recibe los eventos de pago de Polar. La firma del payload se verifica con el estándar Standard Webhooks antes de procesar nada — sin secreto configurado, el endpoint rechaza directo en vez de aceptar sin verificar. Procesa activación, pausa, reanudación y revocación de suscripciones, inicio de prueba gratuita y reembolsos, aplicando los eventos en orden por marca de tiempo para no procesar un evento viejo después de uno más nuevo.
