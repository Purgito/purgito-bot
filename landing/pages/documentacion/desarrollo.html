Desarrollo

Guía técnica para configurar el entorno local, ejecutar la suite de pruebas automatizadas y contribuir al código de Purgito.

Estructura del Repositorio

  • src/bot.py — Punto de entrada del bot de Discord, configuración de intents y carga ordenada de cogs.
  • src/config.py — Módulo centralizado de carga y validación de variables de entorno (.env, urls.env, limits.env).
  • src/db.py — Capa de persistencia asíncrona sobre SQLite (aiosqlite), migraciones automáticas y transacciones.
  • src/webapi.py — Servidor web aiohttp.web con todos los endpoints REST JSON, autenticación OAuth2 y webhooks.
  • src/markov_engine.py — Implementación del motor probabilístico de cadenas de Markov de orden 1 y 2.
  • src/r2.py — Cliente S3 compatible para Cloudflare R2, deduplicación de medios por hash SHA-256 y hashing perceptivo.
  • src/tasks.py — Tareas programadas periódicas (purga diferida de servidores, expiración de auditoría y despachos).
  • src/cogs/ — Cogs de Discord organizados por funcionalidad (chat, gifs, memes, youtube, premium, anuncios, settings, layout_buttons).
  • landing/ — Frontend estático: páginas HTML (landing/pages/), estilos CSS (landing/style.css, landing/dash.css) y JavaScript modular (landing/js/).
  • landing/build_docs.py — Script de compilación de páginas HTML, inyección de layout común y cálculo de hashes de cache-busting.
  • tests/ — Suite de pruebas automatizadas con pytest y pruebas de frontend con Node.js.

Entorno de Desarrollo Local

Requisitos: Python 3.11 o superior (recomendado 3.12) y Node.js 18+ para los tests de frontend.

1. Configuración de archivos de entorno

Purgito utiliza tres archivos de configuración independientes con propósitos específicos:

  • .env: Secretos y tokens de desarrollo (token del bot de Discord, credenciales OAuth2, claves de sesión y webhooks). No versionado en Git. Copiar desde .env.example.
  • urls.env: URLs y endpoints públicos de la aplicación. Versionado en Git.
  • limits.env: Cuotas y límites de almacenamiento por servidor para planes Free y Premium. Versionado en Git.

2. Instalación de dependencias

# Crear y activar entorno virtual
python3 -m venv .venv
source .venv/bin/activate

# Instalar dependencias del bot y herramientas de prueba
pip install -r requirements.txt pytest ruff

Ejecución de Pruebas y Linting

Pruebas unitarias de Python (pytest)

# Ejecutar todos los tests automatizados del bot y la API
.venv/bin/python -m pytest tests -q

# Ejecutar un archivo de test específico
.venv/bin/python -m pytest tests/test_dashboard_routes.py -v

Pruebas de frontend (Node.js)

# Pruebas de integración del dashboard SPA
node landing/test_dash.mjs

# Pruebas de paridad y cobertura de internacionalización (ES / EN)
node landing/test_lang.mjs

Formateo y análisis estático con Ruff

# Verificar estilo y reglas de código
ruff check .

# Formateo automático de código
ruff format .

Generación de documentación y páginas web

Siempre que se modifiquen archivos en landing/pages/, landing/js/, landing/style.css o landing/dash.css, es necesario regenerar las páginas para actualizar los hashes de cache-busting y verificar la paridad entre idiomas:

# Regenerar páginas estáticas en landing/es/ y landing/en/
.venv/bin/python landing/build_docs.py

# Verificar que los archivos generados coincidan exactamente con el repositorio (usado en CI)
.venv/bin/python landing/build_docs.py --check
