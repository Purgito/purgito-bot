Infraestructura

Purgito opera sobre una infraestructura mononodo optimizada en Linux: un proxy inverso Nginx en el borde del servidor, un proceso asíncrono en Python gestionado por systemd y la red de Cloudflare como CDN y capa de seguridad perimetral.

Entorno de Ejecución (Runtime)

El bot y su API web se ejecutan juntos en un único proceso en Python 3.11+ dentro del mismo bucle de eventos asíncrono (asyncio event loop):

  • Gestión con systemd: El servicio bot-purg.service administra el ciclo de vida del proceso en el servidor, gestionando reinicios automáticos tras fallos y redirección de logs hacia journald.
  • Aislamiento de red: La API HTTP (aiohttp) escucha exclusivamente en 127.0.0.1:WEB_PORT (por defecto, puerto 8080/8081). Ningún socket de la aplicación Python está expuesto directamente a internet.

Topología de Nginx

Nginx actúa como único punto de entrada local y separa el tráfico entre contenido estático y dinámico:

Petición entrante (HTTPS)
           │
           ▼
     ┌───────────┐
     │   Nginx   │
     └─────┬─────┘
           │
     ┌─────┴────────────────────────────────┐
     │                                      │
     ▼ Rutas dinámicas                      ▼ Rutas estáticas
/api/*, /auth/*, /webhooks/*, /health       /es/*, /en/*, /assets/*, /style.css
     │                                      │
     ▼ proxy_pass                           ▼ try_files
┌─────────────────────────┐           ┌─────────────────────────┐
│  Python 127.0.0.1:8080  │           │   Directo desde disco   │
│   aiohttp REST API      │           │   (Zero Python CPU)     │
└─────────────────────────┘           └─────────────────────────┘
  • Entrega estática de alto rendimiento: Todas las páginas HTML (landing, guías, documentación, dashboard), estilos CSS, scripts JS e imágenes públicas se sirven directamente desde el sistema de archivos sin despertar al proceso de Python ni consumir memoria de la aplicación.
  • Rutas dinámicas del dashboard: La regla de Nginx redirige cualquier URL con ID de servidor (ej. /es/dashboard/{id}/*) hacia el archivo estático del dashboard correspondiente, permitiendo que la Single Page Application resuelva la ruta en el cliente.
  • Cabeceras de seguridad y caché: Nginx inyecta cabeceras de seguridad (CSP, X-Content-Type-Options, Referrer-Policy) y aplica cabeceras Cache-Control: public, max-age=31536000, immutable a los archivos versionados con hashes de cache-busting (?v=...).

Capa de CDN y Seguridad (Cloudflare)

Cloudflare se sitúa frente al servidor de origen actuando como proxy TLS y red de distribución de contenidos:

  • Terminación TLS 1.3: Gestiona los certificados SSL/TLS y la encriptación hacia el cliente.
  • Caché en el Edge: Almacena en caché los activos estáticos (imágenes, CSS, JS) en centros de datos distribuidos globalmente, absorbiendo el tráfico de la landing y reduciendo la carga sobre el servidor.
  • Mitigación DDoS y WAF: Filtra ataques de denegación de servicio a nivel de red y transporte antes de que alcancen el puerto de Nginx.

Despliegue Continuo sin Paso de Compilación

La arquitectura de Purgito elimina la necesidad de pasos de compilación (build steps) pesados en el servidor:

  1. El código fuente, los scripts y las páginas pregeneradas por landing/build_docs.py están versionados directamente en el repositorio Git.
  2. El despliegue consiste en sincronizar los cambios con git pull.
  3. Se ejecuta la verificación de integridad de la documentación: python3 landing/build_docs.py --check.
  4. Se reinicia el servicio con systemctl restart bot-purg.service, completando la actualización en pocos segundos.
