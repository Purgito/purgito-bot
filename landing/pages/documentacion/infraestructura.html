Infraestructura

Arquitectura de despliegue sobre un único servidor: nginx en el borde, el proceso de Python detrás y Cloudflare como CDN y proxy frontal.

Runtime

El bot y su API corren como un único proceso de Python. La API escucha solo en localhost — nunca expuesta directo a internet — así que nginx es el único punto de entrada real.

Nginx

Nginx separa por ruta: /auth/*, /api/*, /webhooks/* y /health se envían al proceso de Python; todo lo demás — la landing, el dashboard, las páginas legales y esta documentación — se sirve directamente desde archivos estáticos, sin pasar por Python. Como el sitio tiene rutas por idioma (/es/...), la única ruta con un segmento dinámico (el ID de servidor en la URL del dashboard) cuenta con una regla de nginx dedicada; el resto son rutas estáticas en disco.

Cloudflare

Cloudflare actúa como capa de CDN y proxy inverso delante de nginx: gestiona la terminación TLS, protege el servidor de origen y cachea el contenido estático del sitio, reduciendo la carga sobre el servidor.

Despliegue

El despliegue se basa en la sincronización del repositorio: al estar el sitio estático y la documentación pregenerados y versionados en el repositorio, no se requiere un paso de compilación (build step) en el servidor; basta con sincronizar los cambios con git pull y reiniciar el servicio de la aplicación.

Chequeos de salud

/health es un chequeo de vida simple: confirma que el proceso está corriendo y respondiendo, no que la base de datos o la conexión con Discord estén sanas. Existe para monitoreo básico, no como diagnóstico completo del sistema.
