Infrastructure

Despliegue manual sobre un único droplet: nginx en el borde, el proceso de Python detrás, Cloudflare delante de todo.

Runtime

El bot y su API corren como un único proceso de Python. La API escucha solo en localhost — nunca expuesta directo a internet — así que nginx es el único punto de entrada real. Producción corre actualmente bajo una cuenta con privilegios de administrador del sistema en vez de una cuenta dedicada sin privilegios; es una migración pendiente y documentada, no un detalle que esta página deba maquillar.

Nginx

Nginx separa por ruta: /auth/*, /api/*, /webhooks/* y /health se mandan al proceso de Python; todo lo demás — la landing, el dashboard, las páginas legales, esta misma documentación — sale directo de archivos estáticos en el checkout del repo, sin pasar por Python. Como el sitio tiene rutas por idioma (/es/...), la única ruta con un segmento realmente dinámico (el ID de servidor en la URL del dashboard) necesita una regla de nginx propia; el resto son carpetas reales en disco.

Cloudflare

Cloudflare está delante de nginx: termina TLS y cachea el contenido estático del sitio. Si un cambio recién desplegado "no se ve", el diagnóstico habitual es purgar caché antes de sospechar del código.

Deployment

No hay CI/CD: el despliegue es manual — conectarse al droplet, actualizar el checkout con git pull y reiniciar el servicio. Como el HTML de este mismo sitio de documentación se genera y se commitea en el repo (no en el servidor), un git pull alcanza para publicarlo, sin paso de build aparte.

Health Checks

/health es un chequeo de vida simple: confirma que el proceso está corriendo y respondiendo, no que la base de datos o la conexión con Discord estén sanas. Existe para monitoreo básico, no como diagnóstico completo del sistema.
