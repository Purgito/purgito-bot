API

PurgitoのAPIは、aiohttp.web上に構築された非同期のJSON REST インターフェースです。ボットと同じプロセス内で127.0.0.1:WEB_PORTとして動作し、Nginxのリバースプロキシを介して安全にインターネットへ公開されます。

OAuth2認証とセッション

ダッシュボードへのアクセスは、Discordの標準的なOAuth2認可フロー(Authorization Code Flow)を使用します:

  1. GET /auth/loginがsecrets.token_urlsafe(32)で暗号学的に安全なstateパラメータを生成し、identify、email、guildsのスコープを要求してユーザーをDiscordの同意画面にリダイレクトします。
  2. Discordが認可コードとstateを添えてGET /auth/callbackにリダイレクトします。
  3. サーバーはhttps://discord.com/api/v10/oauth2/token経由でコードをアクセストークンに交換し、ユーザーのプロフィールと管理しているサーバー一覧(/users/@me/guilds)を取得します。ユーザーがボットの導入済み・利用可能なサーバーをひとつも管理していない場合、認証は拒否されます。
  4. Fernet(SESSION_SECRET)で対称暗号化した、HttpOnly、SameSite=Lax、Secure属性を持つセッションCookieが発行されます。

メモリ上に重い状態を保持せずにセッションを無効化するため、revoked_sessionsテーブルには、POST /auth/logoutによって明示的に終了されたセッションIDが記録されます。受信するリクエストはすべて、そのセッションIDがこのテーブルに存在しないことを確認します。

サーバー単位のエンドポイント(/api/server/{guild_id}/*)

このプレフィックス配下のルートはすべて、アクティブなセッションが必要で、そのサーバーでユーザーがサーバー管理の権限を持っているかをリアルタイムで検証します:

  • GET/POST /api/server/{id}/style:Purgitoのアバター、ニックネーム、バナーの参照・更新。
  • GET/POST /api/server/{id}/stats:メッセージメモリ、GIF、フレーズ、過去の活動、クォータに関する詳細な指標。
  • GET/PUT /api/server/{id}/chat:生成設定、自発的な応答の割合、メッセージの上限。
  • GET/PUT /api/server/{id}/canales:読み取りチャンネル、応答チャンネル、ミュートされたチャンネル、無視するロールのマトリクス。
  • GET/POST/DELETE /api/server/{id}/gifs:GIFのカタログ、ファイルのアップロード、個別または一括での削除。
  • GET/POST/DELETE /api/server/{id}/memes:ミームバンクのテンプレートと画像。
  • GET/POST/DELETE /api/server/{id}/triggers:完全一致、前方一致、正規表現(regex)による自動応答。
  • GET/POST/DELETE /api/server/{id}/reacciones:絵文字による自動リアクションのルール。
  • GET/POST/DELETE /api/server/{id}/frases:チャンネルごとのカスタムフレーズとテーマ別パック。
  • GET/POST/DELETE /api/server/{id}/embeds:クラシックなembedテンプレートとLayout V2のインタラクティブなブロック。
  • POST /api/server/{id}/embeds/send:デザインしたメッセージをDiscordチャンネルへ即時配信します。
  • GET/PUT/DELETE /api/server/{id}/events/{event_type}:変数エンジンを備えた、歓迎・送別・ブーストイベントの参照、設定(プレーンテキスト、クラシックembed、Layout V2)、リセット。
  • POST /api/server/{id}/events/{event_type}/test:動的変数を解決したテストメッセージを、設定済みのチャンネルへ送信します。
  • GET/POST/DELETE /api/server/{id}/anuncios:自動アナウンスのスケジュール設定と管理。
  • GET/POST/DELETE/PATCH /api/server/{id}/youtube:新着動画の購読と通知先チャンネル。
  • GET/POST/DELETE/PATCH /api/server/{id}/rss:汎用RSS/Atomフィードの購読と、新着投稿の通知先チャンネル。
  • POST /api/server/{id}/amnesia:過去24時間で学習したメッセージコーパスと文体のクリア。
  • GET /api/server/{id}/audit:ダッシュボードから行われた変更の監査ログ。

支払いのWebhook(Polar)

POST /webhooks/polarは、Polarが発行するサブスクリプションと請求に関するイベント通知を受け取ります:

  • 署名の検証:Webhook-Signatureヘッダーを、POLAR_WEBHOOK_SECRETを使ったStandard Webhooksの標準(HMAC-SHA256)に基づいて検証します。署名が不正、またはヘッダーが欠けている場合、リクエストは400で拒否されます。
  • イベントの順序:各ペイロードにはタイムスタンプが含まれており、ネットワーク上で遅延したイベントが、より新しい状態を上書きしないことを保証します。
  • 処理されるイベント:subscription.created、subscription.updated、subscription.active、subscription.canceled、order.refundedで、これらはguild_premiumテーブルをリアルタイムに更新します。
