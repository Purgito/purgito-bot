インフラストラクチャ

Purgitoは、最適化されたLinuxの単一ノード上で動作します:サーバーの入り口に立つNginxのリバースプロキシ、systemdが管理する非同期のPythonプロセス、そしてCDN兼境界のセキュリティレイヤーとなるCloudflareのネットワークです。

実行環境(Runtime)

ボットとそのWeb APIは、同じ非同期イベントループ(asyncioイベントループ)の中で、Python 3.11+の単一プロセスとして一緒に動作します:

  • systemdによる管理:bot-purg.serviceというサービスが、サーバー上でのプロセスのライフサイクルを管理し、障害発生後の自動再起動や、journaldへのログの転送を担当します。
  • ネットワークの分離:HTTP API(aiohttp)は127.0.0.1:WEB_PORT(デフォルトはポート8080/8081)でのみ待ち受けます。Pythonアプリケーションのソケットがインターネットに直接公開されることはありません。

Nginxのトポロジー

Nginxは唯一のローカルな入口として機能し、静的なコンテンツと動的なコンテンツのトラフィックを振り分けます:

受信リクエスト (HTTPS)
           │
           ▼
     ┌───────────┐
     │   Nginx   │
     └─────┬─────┘
           │
     ┌─────┴────────────────────────────────┐
     │                                      │
     ▼ 動的なルート                          ▼ 静的なルート
/api/*, /auth/*, /webhooks/*, /health       /es/*, /en/*, /assets/*, /style.css
     │                                      │
     ▼ proxy_pass                           ▼ try_files
┌─────────────────────────┐           ┌─────────────────────────┐
│  Python 127.0.0.1:8080  │           │    ディスクから直接配信   │
│   aiohttp REST API      │           │   (PythonのCPUを使わない) │
└─────────────────────────┘           └─────────────────────────┘
  • 高速な静的コンテンツ配信:HTMLページ(ランディング、ガイド、ドキュメント、ダッシュボード)、CSSスタイル、JSスクリプト、公開画像はすべて、Pythonプロセスを起こしたりアプリケーションのメモリを消費したりすることなく、ファイルシステムから直接配信されます。
  • ダッシュボードの動的ルート:サーバーIDを含むURL(例:/es/dashboard/{id}/*)に対するNginxのルールは、対応するダッシュボードの静的ファイルへリダイレクトし、シングルページアプリケーションがクライアント側でルートを解決できるようにします。
  • セキュリティとキャッシュのヘッダー:Nginxはセキュリティヘッダー(CSP、X-Content-Type-Options、Referrer-Policy)を付与し、キャッシュバスティング用のハッシュ(?v=...)が付いたバージョン管理済みファイルにはCache-Control: public, max-age=31536000, immutableヘッダーを適用します。

CDNとセキュリティレイヤー(Cloudflare)

Cloudflareはオリジンサーバーの手前に位置し、TLSプロキシおよびコンテンツ配信ネットワークとして機能します:

  • TLS 1.3の終端:SSL/TLS証明書とクライアントへの暗号化を管理します。
  • エッジでのキャッシュ:静的アセット(画像、CSS、JS)を世界中に分散したデータセンターにキャッシュし、ランディングページのトラフィックを吸収してサーバーの負荷を軽減します。
  • DDoS対策とWAF:サービス拒否攻撃を、Nginxのポートに到達する前にネットワーク・トランスポート層でフィルタリングします。

ビルドステップなしの継続的デプロイ

Purgitoのアーキテクチャは、サーバー上での重いビルドステップ(build step)を不要にします:

  1. ソースコード、スクリプト、landing/build_docs.pyによって事前生成されたページはすべて、Gitリポジトリに直接バージョン管理されています。
  2. デプロイはgit pullで変更を同期するだけです。
  3. ドキュメントの整合性チェック:python3 landing/build_docs.py --checkを実行します。
  4. systemctl restart bot-purg.serviceでサービスを再起動し、数秒で更新が完了します。
