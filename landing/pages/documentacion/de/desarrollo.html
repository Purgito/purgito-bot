Entwicklung

Technische Anleitung zum Einrichten der lokalen Umgebung, zum Ausführen der automatisierten Testsuite und zum Beitragen zum Code von Purgito.

Struktur des Repositorys

  • src/bot.py — Einstiegspunkt des Discord-Bots, Konfiguration der Intents und geordnetes Laden der Cogs.
  • src/config.py — Zentrales Modul zum Laden und Validieren der Umgebungsvariablen (.env, urls.env, limits.env).
  • src/db.py — Asynchrone Persistenzschicht über SQLite (aiosqlite), automatische Migrationen und Transaktionen.
  • src/webapi.py — Webserver aiohttp.web mit allen JSON-REST-Endpunkten, OAuth2-Authentifizierung und Webhooks.
  • src/markov_engine.py — Implementierung der probabilistischen Markov-Ketten-Engine erster und zweiter Ordnung.
  • src/r2.py — S3-kompatibler Client für Cloudflare R2, Mediendeduplizierung per SHA-256-Hash und perzeptuelles Hashing.
  • src/tasks.py — Periodische geplante Aufgaben (verzögerte Löschung von Servern, Ablauf der Audit-Daten und Versandaufgaben).
  • src/cogs/ — Discord-Cogs, organisiert nach Funktion (chat, gifs, memes, youtube, rss, premium, anuncios, settings, layout_buttons).
  • landing/ — Statisches Frontend: HTML-Seiten (landing/pages/), CSS-Stile (landing/style.css, landing/dash.css) und modulares JavaScript (landing/js/).
  • landing/build_docs.py — Build-Skript für HTML-Seiten, Einfügen des gemeinsamen Layouts und Berechnung der Cache-Busting-Hashes.
  • tests/ — Automatisierte Testsuite mit pytest und Frontend-Tests mit Node.js.

Lokale Entwicklungsumgebung

Voraussetzungen: Python 3.11 oder höher (empfohlen 3.12) und Node.js 18+ für die Frontend-Tests.

1. Konfiguration der Umgebungsdateien

Purgito nutzt drei unabhängige Konfigurationsdateien mit jeweils eigenem Zweck:

  • .env: Secrets und Entwicklungs-Tokens (Token des Discord-Bots, OAuth2-Zugangsdaten, Sitzungsschlüssel und Webhooks). Nicht in Git versioniert. Von .env.example kopieren.
  • urls.env: URLs und öffentliche Endpunkte der Anwendung. In Git versioniert.
  • limits.env: Kontingente und Speicherlimits pro Server für die Pläne Free und Premium. In Git versioniert.

2. Installation der Abhängigkeiten

# Virtuelle Umgebung erstellen und aktivieren
python3 -m venv .venv
source .venv/bin/activate

# Abhängigkeiten des Bots und Testwerkzeuge installieren
pip install -r requirements.txt pytest ruff

Tests ausführen und Linting

Python-Unit-Tests (pytest)

# Alle automatisierten Tests von Bot und API ausführen
.venv/bin/python -m pytest tests -q

# Eine bestimmte Testdatei ausführen
.venv/bin/python -m pytest tests/test_dashboard_routes.py -v

Frontend-Tests (Node.js)

# Integrationstests des Dashboard-SPA
node landing/test_dash.mjs

# Paritäts- und Abdeckungstests der Internationalisierung (ES / EN)
node landing/test_lang.mjs

Formatierung und statische Analyse mit Ruff

# Codestil und Regeln prüfen
ruff check .

# Code automatisch formatieren
ruff format .

Generierung von Dokumentation und Webseiten

Immer wenn Dateien in landing/pages/, landing/js/, landing/style.css oder landing/dash.css geändert werden, müssen die Seiten neu generiert werden, um die Cache-Busting-Hashes zu aktualisieren und die Parität zwischen den Sprachen zu prüfen:

# Statische Seiten in landing/es/ und landing/en/ neu generieren
.venv/bin/python landing/build_docs.py

# Prüfen, dass die generierten Dateien exakt mit dem Repository übereinstimmen (in CI verwendet)
.venv/bin/python landing/build_docs.py --check
