Discord

Purgito is built on discord.py and structured as a modular collection of cogs. Each cog encapsulates application slash commands, Gateway event listeners, and asynchronous periodic routines.

Bot Structure and Cogs

The bot entrypoint (src/bot.py) initializes the commands.Bot instance with the minimum required intents: guilds, message_content, emojis_and_stickers, and reactions. Cogs are loaded asynchronously during setup_hook in a deliberate order:

CogModuleTechnical Responsibility
premiumsrc/cogs/premium.pyQuota verification and Premium status checks (is_premium_guild). Loaded first to expose quota helpers to other cogs.
chatsrc/cogs/chat.pyMessage capture, cleaning for the corpus, reply probability evaluation, Markov engine invocation, and mention handling.
gifssrc/cogs/gifs.pyGIF detection in messages, native URL extraction (Tenor/Giphy), optional compression, and deduplicated uploads to Cloudflare R2.
memessrc/cogs/memes.pyServer image gallery, meme template rendering, caption generation via Markov or Groq AI, and emoji reaction capture.
youtubesrc/cogs/youtube.pyPeriodic monitoring of YouTube RSS channel feeds and automatic alert dispatching to configured Discord channels.
anunciossrc/cogs/anuncios.pyAutomated announcement scheduler: dispatches embeds and messages at recurring intervals or fixed times with timezone support.
generalsrc/cogs/general.pyGeneral commands (/ping, /ayuda), global command synchronization, and guild lifecycle handling.
settingssrc/cogs/settings.pyNative in-Discord interactive panel (views, selects, buttons) and onboarding greeting upon joining new servers.
layout_buttonssrc/cogs/layout_buttons.pyInteractive components controller (Layout V2): role assignment/removal, external URLs, and modal dialogs.
eventssrc/cogs/events.pyServer events: Welcome, Goodbye, and Boosts with dynamic variable resolution ({user}, {server_membercount_ordinal}, etc.), 3 content modes, and secure channel dispatching.

Gateway Event Lifecycle

Cogs subscribe to events emitted by the Discord Gateway WebSocket (requiring intents.members = True for member events):

  • on_ready: Fired when the bot completes identification with the Gateway. Syncs application slash commands and starts periodic background tasks in src/tasks.py.
  • on_message: Pipeline execution: bot filtering, allowed/silenced channel checks, insertion into the corpus table, trigger evaluation, and response generation.
  • on_member_join: Detects new member joins and dispatches the configured Welcome message.
  • on_member_remove: Detects member departures and dispatches the configured Goodbye message.
  • on_member_update: Idempotently detects boost transitions and dispatches the configured Boost thank you message.
  • on_raw_reaction_add: Captures reactions for automatic emoji triggers and meme image collection.
  • on_guild_join: Inserts the server into the database, sets default configuration, and posts the welcome onboarding guide.
  • on_guild_remove: Marks the server with a left_at timestamp in the database, starting the retention grace period before permanent purging.
  • on_guild_channel_update: Updates cached channel metadata to keep the web dashboard synchronized.

Error Handling and Interactions

Application slash commands use Discord's command tree (app_commands.CommandTree). Interaction errors are intercepted by a global on_app_command_error handler:

  • app_commands.MissingPermissions: Informs the user that they lack required permissions (e.g., Manage Server) via an ephemeral message.
  • app_commands.BotMissingPermissions: Lists missing channel permissions required by Purgito (e.g., Send Messages, Embed Links, Attach Files).
  • app_commands.CommandOnCooldown: Displays remaining cooldown time to prevent spam on intensive operations.

Permissions and Hierarchy

Purgito delegates authorization directly to Discord's native permission system. It does not maintain a separate roles table: all checks inspect interaction.user.guild_permissions. For administrative member actions (such as role assignment via Layout V2 buttons), the bot verifies that its own highest role sits above the target role in the server's role hierarchy.
