Discord

Purgito is a discord.py bot structured as a collection of cogs — each with one responsibility — loaded when the process starts.

Bot and cogs

The entrypoint (src/bot.py) loads cogs in a deliberate order: premium first, because it exposes is_premium_guild to the rest.

CogResponsibility
premiumPer-server Premium status, managed from the dashboard.
chatCorpus, Markov chains, and automatic replies.
gifsGIF capture and management: detecting them in messages, uploading to R2, web gallery.
memesMemes: command, automatic generation, image capture via reaction.
youtubeYouTube notifications via RSS.
anunciosMessages scheduled to a channel, on an interval or at a fixed time.
generalHelp command, ping, errors, and server lifecycle.
settingsUnified settings panel and onboarding when joining a server.
layout_buttonsFunctional actions for the embed editor's buttons (Layout V2).

Events

Besides on_ready (startup, syncs slash commands and starts the web API), cogs listen for the events they need: on_message (chat, GIF capture, meme capture by reaction), on_guild_join/on_guild_remove (lifecycle — leaving a server schedules the deferred deletion of its data), on_raw_reaction_add (meme capture), and on_guild_channel_update. Slash command errors don't go through the same channel as prefix command errors, so they have their own handler (on_app_command_error), wired by hand instead of with the standard decorator.

Permissions

There's no role system of the bot's own: every permission check looks directly at Discord's native permissions. Admin actions (opening the settings panel, changing settings) verify that whoever invokes them has Manage Server. Before running an action that needs the bot's own permissions — like assigning a role from an embed button — the bot checks its own permissions and role hierarchy, not just those of whoever clicked.

Interactions

Practically every command is a slash command; !ping is the only prefix-command exception. Panels and menus are built with discord.py views (buttons, selects), and every view restricts who can use it to whoever opened it — a settings button meant for someone else doesn't respond if you click it.
