Security

Purgito's security architecture is founded on zero-trust client boundaries, defense in depth, and strict data isolation by design.

OAuth2 Authentication and Encrypted Cookies

User identification is delegated entirely to Discord via standard OAuth2 (Authorization Code Flow):

  • No Password Storage: Purgito never accepts, handles, or stores user passwords or raw Discord credentials.
  • Symmetric Session Encryption: Session payloads are encrypted using Fernet (AES-128 in CBC mode with HMAC-SHA256 authentication) with the SESSION_SECRET key.
  • Cookie Security Attributes: Cookies are configured with HttpOnly (mitigating XSS extraction via JavaScript), Secure (only transmitted over TLS), and SameSite=Lax (guarding against cross-site request forgery).
  • Server-Side Revocation List: The revoked_sessions table records terminated session IDs on logout, ensuring immediate invalidation even if a valid cookie remains present in a client browser.

Real-Time Authorization and Zero Trust

No administrative API request trusts client-declared claims (such as request body IDs or custom headers):

  • Live Revalidation Against Discord API: Whenever a user interacts with a server in the dashboard (/api/server/{guild_id}/*), the server queries Discord's /users/@me/guilds in real time using the OAuth access token.
  • Native Permission Validation: Operations require the MANAGE_GUILD or ADMINISTRATOR permission. There are no synthetic database roles that could drift out of sync with Discord.
  • Bot Role Hierarchy Enforcement: Actions performed by Layout V2 interactive buttons (such as assigning roles) verify that Purgito's highest role is positioned above the target role in the server's role hierarchy, preventing privilege escalations.

SSRF Defense and Asset Ingestion

When the bot fetches remote images or GIFs from user-supplied URLs or webhooks:

  • Secure DNS Resolution: Target hostnames are resolved before opening HTTP connections. Requests attempting to reach private IPv4/IPv6 subnets (RFC 1918), local loopback (127.0.0.1, ::1), or cloud metadata endpoints (e.g., 169.254.169.254) are blocked immediately.
  • Magic Number Verification: Downloaded streams are validated against binary magic bytes to guarantee legitimate image formats (PNG, JPEG, GIF, WEBP), preventing malicious executable uploads.

Multi-Layer Rate Limiting and Abuse Prevention

Purgito employs rate limiters across independent operational layers:

  • IP Rate Limiting on Public API: Shields public endpoints (/health, /api/status, /auth/*) against denial-of-service attempts and aggressive web crawlers.
  • User Command Cooldowns: Enforces per-user cooldowns on CPU-intensive Discord commands (meme rendering, member imitation, channel refeeding).
  • Channel Reply Throttling: Enforces a minimum interval between spontaneous replies within the same channel to eliminate chat spam.
  • Global CPU Semaphore: Caps simultaneous Markov model compilations process-wide, ensuring no single server can starve shared CPU capacity.
