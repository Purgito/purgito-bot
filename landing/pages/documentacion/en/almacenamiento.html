Storage

Purgito uses a hybrid storage architecture combining an embedded local SQLite database for relational state with an S3-compatible object store (Cloudflare R2) for media assets.

SQLite Database Architecture

All relational state resides in a single database file: data/bot.db. Asynchronous database connectivity is handled via aiosqlite in src/db.py with production pragmas:

  • PRAGMA journal_mode=WAL: Write-Ahead Logging allows concurrent read operations without blocking writes, drastically reducing disk lock contention.
  • PRAGMA synchronous=NORMAL: Ensures data integrity during host failures with minimal I/O wait latency.
  • PRAGMA foreign_keys=ON: Enforces relational integrity across cascaded record deletions.
  • Asynchronous Write Lock: A dedicated Python asyncio.Lock serializes write transactions process-wide, preventing database is locked errors under high concurrency.

Schema and Data Isolation

The database features over 20 tables organized by operational domain. Guild multi-tenancy is enforced at schema level via indexed guild_id columns across every table:

  • Configuration and Customization: guild_settings, guild_style, channel_settings, ignored_roles, silenced_channels.
  • Learning Corpus: corpus (channel messages) and user_corpus (author messages), both backed by composite indices on (guild_id, created_at) for rapid model sampling and trimming.
  • Automation and Triggers: triggers, custom_reactions, custom_phrases, phrase_packs, scheduled_announcements.
  • Server Events: server_events (welcome, goodbye, and boost configurations per guild), member_boost_records (idempotent boost timestamp tracking).
  • Message Designer: embed_templates, layout_v2_blocks, embed_share_links.
  • Security and Billing: revoked_sessions, guild_premium, audit_log.

Cloudflare R2 and Media Deduplication

Object storage on Cloudflare R2 (src/r2.py) is optional. When the five R2 environment variables are configured in .env, Purgito activates asset ingestion, optimization, and hosting:

  • Content-Addressable Storage (SHA-256): Stored media objects are named after the SHA-256 hash of their payload. If multiple servers save the same GIF, only one copy exists in the R2 bucket.
  • Perceptual Hashing (pHash): Computes an image hash via imagehash.phash to detect visually duplicate images despite varying compression or container headers.
  • Reference Counting: The gif_objects table maintains an active reference counter. When a server deletes a GIF, the counter decrements; the object is physically purged from R2 only when the reference count drops to zero.
  • SSRF Protection on Download: Media fetch routines validate that remote URLs do not resolve to private subnets (RFC 1918), local loopback (127.0.0.1), or cloud metadata endpoints.

Retention Policies and Background Sweeps

The src/tasks.py module executes scheduled maintenance coroutines:

  • Guild Removal Grace Period: When the bot is removed from a server (on_guild_remove), a left_at timestamp is recorded. A daily background job permanently purges the guild's data only after GUILD_DATA_RETENTION_DAYS (default: 30 days) have elapsed. Re-inviting the bot before this window expires automatically cancels the purge.
  • Audit Log Expiration: Records in audit_log exceeding AUDIT_LOG_RETENTION_DAYS (default: 90 days) are pruned automatically.
  • Share Links: Ephemeral share URLs for embed templates generated in the dashboard expire and are deleted after 24 hours.
  • Revoked Sessions: Expired session IDs in revoked_sessions are periodically cleaned up to maintain small table footprints.
