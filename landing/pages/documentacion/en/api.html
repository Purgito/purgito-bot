API

Purgito's API is an asynchronous JSON REST interface built on aiohttp.web. It runs within the same process as the bot on 127.0.0.1:WEB_PORT and is securely exposed to the internet via Nginx's reverse proxy.

OAuth2 Authentication and Sessions

Dashboard access uses Discord's standard OAuth2 authorization flow (Authorization Code Flow):

  1. GET /auth/login generates a cryptographically secure state parameter using secrets.token_urlsafe(32) and redirects the user to Discord's consent screen requesting the scopes identify, email, and guilds.
  2. Discord redirects back to GET /auth/callback with the authorization code and state.
  3. The server exchanges the code for an access token via https://discord.com/api/v10/oauth2/token, fetches the user's profile, and retrieves the guilds they administer (/users/@me/guilds). If the user does not manage any server where the bot is installed or available, authentication is rejected.
  4. A session cookie is issued, symmetrically encrypted using Fernet (SESSION_SECRET) with HttpOnly, SameSite=Lax, and Secure flags.

To invalidate sessions without maintaining heavy state in memory, the revoked_sessions table records explicitly terminated session identifiers upon POST /auth/logout. Every incoming request verifies that its session ID is absent from this table.

Guild Endpoints (/api/server/{guild_id}/*)

All routes under this prefix require an active session and verify in real time that the user holds the Manage Server permission (or the more limited Manager role) on the target guild:

  • GET /api/server/{id}/channels, /roles, /emojis: Raw guild lists feeding the panel's selectors.
  • GET/POST /api/server/{id}/style: Query and update Purgito's avatar, nickname, and banner on the server.
  • GET/POST /api/server/{id}/stats, GET .../stats/activity: Memory metrics for messages, GIFs, phrases, historical activity, and quotas.
  • GET/PUT /api/server/{id}/settings/chat, PUT .../settings/chat/tunables: Generation parameters, reply probabilities, and message limits.
  • POST /api/server/{id}/chat/playground: Chat response simulator that doesn't post anything to Discord.
  • GET/PUT /api/guilds/{id}/channels/{channel_id}/settings: Per-channel override of chat settings.
  • GET/POST/DELETE /api/server/{id}/settings/spontaneous-channels: Channels where the bot talks on its own.
  • GET/POST/DELETE /api/server/{id}/settings/mention-channels: Channels where it replies to mentions.
  • GET/POST/DELETE /api/server/{id}/settings/corpus, POST .../settings/corpus/amnesia: Channels it learns from, and corpus wipe. Fully silenced channels (ignored_channels) have no dedicated endpoint — they're managed via /settings in Discord.
  • GET/POST/DELETE /api/server/{id}/settings/exempt-roles, .../settings/exempt-channels: Roles and channels exempt from the mention rate limit.
  • GET/POST/PUT/DELETE /api/server/{id}/settings/excluded-users: Users excluded from learning.
  • GET /api/server/{id}/members/search: Member search for the panel's selectors.
  • GET/POST/DELETE /api/server/{id}/settings/reacciones: Automated emoji reaction rules.
  • GET/POST/DELETE/PATCH /api/server/{id}/settings/frases (+ /channels) and /api/server/{id}/frases/packs (+ /channels): Special phrases, their assigned channels, and their packs.
  • GET/POST/DELETE /api/server/{id}/settings/triggers: Automatic triggers matching exact text, prefixes, or regular expressions.
  • GET/PUT /api/server/{id}/settings/updates, .../settings/prefix, .../settings/manager-role: Updates channel, command prefix, and the server's Manager role.
  • GET/POST/DELETE /api/server/{id}/settings/gifs (+ /senders, /by-user/{user_id}, /verify, /blocked, /{gif_id}/block): GIF catalog, per-user attribution, verification, and blocklist.
  • GET/POST/DELETE/PATCH /api/server/{id}/youtube, /twitch, /rss: YouTube, Twitch, and generic RSS/Atom feed subscriptions and alert destinations.
  • POST /api/server/{id}/embeds/send, /share, /schedule, /validate, /upload, /upload-file/{filename}, /resolve-gif, GET .../uploads: Embed editor — sending, share links, scheduling, validation, and file uploads.
  • GET/POST/PUT/DELETE /api/server/{id}/embeds/templates: Saved message designer templates.
  • GET/POST/PUT/DELETE /api/server/{id}/anuncios: Automated announcement scheduling and management.
  • GET/PUT/DELETE /api/server/{id}/events, /events/{event_type}, POST .../test: Query, configure (plain text, classic embed, Layout V2), and test Welcome, Goodbye, and Boost server events with the placeholder engine.
  • GET /api/server/{id}/premium, POST .../premium/checkout: The server's Premium status and starting a Polar checkout session.
  • GET /api/guilds/{id}/audit: Audit log recording actions taken via the dashboard (note the /guilds/ prefix, unlike the rest).

There's no dedicated endpoint for meme bank images yet: that feature is managed entirely from Discord (reactions and commands), with no dashboard surface so far.

Payment Webhooks (Polar)

POST /webhooks/polar receives subscription and billing lifecycle events sent by Polar:

  • Signature verification: The Webhook-Signature header is validated against the Standard Webhooks specification (HMAC-SHA256) using POLAR_WEBHOOK_SECRET. Invalid or missing signatures return HTTP 400.
  • Event ordering: Payload timestamps ensure out-of-order delivery over the network cannot overwrite newer subscription states.
  • Supported events: subscription.active and subscription.resumed grant Premium; subscription.paused and subscription.revoked remove it; subscription.created with a trialing status counts as a new grant (starts the 7-day trial); refund.created/refund.updated revoke access once the refund is confirmed and the object carries revoke_benefits. All of this updates the premium_guilds table in real time. subscription.updated/subscription.canceled don't grant or remove access on their own, but do update the billing metadata in premium_subscriptions (plan, period, scheduled cancellation) that feeds /perfil/facturacion.
