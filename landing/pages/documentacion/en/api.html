API

Purgito's API is pure JSON over aiohttp — it doesn't render HTML on any endpoint. It runs in the same process as the bot, listening only on localhost; nginx is what exposes it externally under /api/*, /auth/*, and /webhooks/*.

Overview

Two categories of endpoints: a handful of public ones with no session (health check, bot status, the payment webhook), and the per-server endpoints under /api/server/{guild_id}/..., which require an authenticated session and require whoever is calling to administer that specific server.

Authentication

Standard Discord OAuth2 (Authorization Code flow), implemented directly on aiohttp with no OAuth library. Login redirects to Discord; the callback exchanges the code for a token, fetches the user and their servers, and builds the session. If the user doesn't administer any server, the login is rejected.

Sessions

The session lives entirely encrypted in the cookie (no session table on the server) — httpOnly, SameSite=Lax, marked secure. Since a stolen encrypted cookie would still be valid until it expires, logout alone isn't enough: each login generates an identifier that goes into a revocation list in the database, and every request re-checks that that identifier hasn't been revoked.

Per-server — /api/server/{guild_id}/...

Require a session, the Manage Server permission verified live against Discord, and the bot being present on that server. Grouped by area — each group has its own set of GET/PUT/ POST/DELETE routes:

  • Server metadata: channels, roles, emojis, statistics.
  • Chat settings: probabilities, spontaneous/mention channels, per-channel overrides, test playground.
  • Roles and channels exempt from the mention rate limit.
  • Corpus: adding, deleting, "amnesia" (resetting the last 24 hours).
  • Automatic reactions and special phrases, including reusable packs.
  • Configurable triggers (regex, exact text, starts-with).
  • The server's GIF gallery.
  • YouTube subscriptions.
  • Embed editor: templates, sending, scheduling, uploading images/files, shareable links.
  • Premium status and starting checkout.
  • Audit log of changes made from the panel.

Webhooks

POST /webhooks/polar receives Polar's payment events. The payload's signature is verified with the Standard Webhooks spec before processing anything — with no secret configured, the endpoint rejects outright instead of accepting unverified. It processes activation, pause, resumption, and revocation of subscriptions, free-trial start, and refunds, applying events in timestamp order so an older event never gets processed after a newer one.
