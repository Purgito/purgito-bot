API

Purgito's API is an asynchronous JSON REST interface built on aiohttp.web. It runs within the same process as the bot on 127.0.0.1:WEB_PORT and is securely exposed to the internet via Nginx's reverse proxy.

OAuth2 Authentication and Sessions

Dashboard access uses Discord's standard OAuth2 authorization flow (Authorization Code Flow):

  1. GET /auth/login generates a cryptographically secure state parameter using secrets.token_urlsafe(32) and redirects the user to Discord's consent screen requesting the scopes identify, email, and guilds.
  2. Discord redirects back to GET /auth/callback with the authorization code and state.
  3. The server exchanges the code for an access token via https://discord.com/api/v10/oauth2/token, fetches the user's profile, and retrieves the guilds they administer (/users/@me/guilds). If the user does not manage any server where the bot is installed or available, authentication is rejected.
  4. A session cookie is issued, symmetrically encrypted using Fernet (SESSION_SECRET) with HttpOnly, SameSite=Lax, and Secure flags.

To invalidate sessions without maintaining heavy state in memory, the revoked_sessions table records explicitly terminated session identifiers upon POST /auth/logout. Every incoming request verifies that its session ID is absent from this table.

Guild Endpoints (/api/server/{guild_id}/*)

All routes under this prefix require an active session and verify in real time that the user holds the Manage Server permission on the target guild:

  • GET/POST /api/server/{id}/style: Query and update Purgito's avatar, nickname, and banner on the server.
  • GET/POST /api/server/{id}/stats: Detailed memory metrics for messages, GIFs, phrases, historical activity, and quotas.
  • GET/PUT /api/server/{id}/chat: Generation parameters, spontaneous reply probabilities, and conversation limits.
  • GET/PUT /api/server/{id}/canales: Matrix of reading channels, reply channels, silenced channels, and ignored roles.
  • GET/POST/DELETE /api/server/{id}/gifs: GIF catalog, file uploads, and single/bulk deletion.
  • GET/POST/DELETE /api/server/{id}/memes: Server meme image templates and assets.
  • GET/POST/DELETE /api/server/{id}/triggers: Automatic triggers matching exact text, prefixes, or regular expressions.
  • GET/POST/DELETE /api/server/{id}/reacciones: Automated emoji reaction rules.
  • GET/POST/DELETE /api/server/{id}/frases: Custom static phrases and themed pack definitions.
  • GET/POST/DELETE /api/server/{id}/embeds: Saved templates for classic embeds and interactive Layout V2 blocks.
  • POST /api/server/{id}/embeds/send: Immediate dispatch of a designed message to a Discord channel.
  • GET/PUT/DELETE /api/server/{id}/events/{event_type}: Query, configure (plain text, classic embed, Layout V2), and reset Welcome, Goodbye, and Boost server events with the placeholder engine.
  • POST /api/server/{id}/events/{event_type}/test: Send a test event message with resolved placeholders to the configured channel.
  • GET/POST/DELETE /api/server/{id}/anuncios: Automated announcement scheduling and management.
  • GET/POST/DELETE /api/server/{id}/youtube: YouTube channel feed subscriptions and alert destinations.
  • POST /api/server/{id}/amnesia: Purges messages and style learned within the last 24 hours.
  • GET /api/server/{id}/audit: Audit log recording actions taken via the dashboard.

Payment Webhooks (Polar)

POST /webhooks/polar receives subscription and billing lifecycle events sent by Polar:

  • Signature verification: The Webhook-Signature header is validated against the Standard Webhooks specification (HMAC-SHA256) using POLAR_WEBHOOK_SECRET. Invalid or missing signatures return HTTP 400.
  • Event ordering: Payload timestamps ensure out-of-order delivery over the network cannot overwrite newer subscription states.
  • Supported events: subscription.created, subscription.updated, subscription.active, subscription.canceled, and order.refunded, updating the guild_premium table in real time.
