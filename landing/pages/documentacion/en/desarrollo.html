Development

Project structure

  • src/cogs/ — the bot's commands and features (chat, gifs, memes, youtube, premium, announcements, layout_buttons, settings, general).
  • src/webapi.py — the full JSON API.
  • landing/ — the static site: index.html, style.css, script.js.
  • landing/pages/ — hand-written page bodies; build_docs.py adds the navbar/footer/head to them.
  • landing/js/ + landing/dash.css — the dashboard, native ES modules with no bundler.
  • data/bot.db — the SQLite database.

Local environment

The bot is Python 3.11+; CI runs on 3.12. Three environment files with different rules: .env (secrets, not versioned — expected names in .env.example), urls.env (public URLs, versioned), and limits.env (per-server quotas, versioned). All three are loaded when src/config.py is imported.

Tests

# pytest isn't in requirements.txt — use the project's venv.
.venv/bin/python -m pytest tests -q

# Lint and formatting, run in CI.
ruff check .
ruff format --check .

# Regenerates the landing/es/ and landing/en/ pages — run after touching
# docs/*.md, landing/pages/*, or any .css or .js file.
.venv/bin/python landing/build_docs.py
.venv/bin/python landing/build_docs.py --check

There's no pytest.ini: tests are discovered automatically from tests/.
