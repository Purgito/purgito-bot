Infrastructure

Deployment architecture on a single server: nginx at the edge, the Python process behind it, and Cloudflare as the CDN and front proxy.

Runtime

The bot and its API run as a single Python process. The API listens only on localhost — never exposed directly to the internet — so nginx is the only real entry point.

Nginx

Nginx splits by route: /auth/*, /api/*, /webhooks/*, and /health go to the Python process; everything else — the landing page, the dashboard, the legal pages, and this documentation — is served directly from static files, never touching Python. Since the site has per-language routes (/es/..., /en/...), the one route with a dynamic segment (the server ID in the dashboard URL) has a dedicated nginx rule; everything else is static routes on disk.

Cloudflare

Cloudflare acts as a CDN and reverse proxy layer in front of nginx: it handles TLS termination, protects the origin server, and caches the site's static content, reducing load on the server.

Deployment

Deployment is based on syncing the repository: since the static site and the documentation are pre-generated and versioned in the repository, no build step is required on the server; syncing changes with git pull and restarting the application service is enough.

Health checks

/health is a simple liveness check: it confirms the process is running and responding, not that the database or the connection to Discord are healthy. It exists for basic monitoring, not as a full system diagnostic.
